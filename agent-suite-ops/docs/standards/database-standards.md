# MySQL企业级数据库标准

## 1. 数据库边界

| 权限域 | 数据库 | 运行权限 |
|---|---|---|
| 法律咨询 | `legal_agent_db` | 本服务业务账号读写；迁移账号独立 |
| 智能招聘 | `recruitment_agent_db` | 本服务业务账号读写；迁移账号独立 |
| 智能问数运行态 | `data_query_agent_db` | 智能问数服务读写 |
| 课件电商数据 | `shop_db` | 智能问数查询账号只读；MCP使用该账号 |

禁止跨 Agent schema JOIN、共享业务表或复用高权限账号。开发环境可共用 MySQL 实例，部署配置允许拆分实例。

## 2. 基础约定

- MySQL 8，InnoDB，`utf8mb4`；所有连接显式设置字符集。
- 数据库存储 UTC；API 使用 ISO 8601 并明确时区。
- 表、列、索引、约束使用 snake_case 英文命名。
- 新业务表优先使用复数名；课件 `shop_db` 原有表名保持不变。
- 每表必须有主键；外键、唯一约束和非空约束表达真实业务不变量。
- 不默认软删除；只有审计/恢复需求明确时增加 `deleted_at`。

## 3. 字段标准

- 内部关系主键：`BIGINT UNSIGNED`；公开 API 使用独立不可预测 `public_id`，不暴露自增ID。
- 时间：`DATETIME(6)`，常用字段为 `created_at`、`updated_at`；由数据库/应用统一约定写入责任。
- 金额：`DECIMAL`，禁止 float/double。
- 状态/枚举：集中版本化定义；稳定状态可加 CHECK，变化频繁的业务字典进入配置/字典表。
- 文本长度按数据证据设置；禁止无理由全部使用 TEXT/VARCHAR(255)。
- JSON 只用于非核心、低查询频率、结构可演进数据；需要检索/约束的字段必须结构化。
- PII字段必须最小化、分权、脱敏；需要加密的字段在详细设计标注算法和密钥管理。

## 4. 索引与查询

- 索引来自已确认查询模式，不为每列盲目建索引。
- 联合索引按过滤、等值、范围、排序和覆盖需求设计并记录理由。
- 所有外键列评估索引；唯一业务键必须唯一约束，不只靠应用检查。
- 列表接口必须分页；禁止无上限全表读取。
- 避免N+1；复杂查询使用执行计划和基准数据验证。
- 智能问数查询额外执行AST白名单、行数、超时和结果大小限制。

## 5. 事务与并发

- 一个业务用例定义一个清晰事务边界，事务尽量短。
- 外部DeepSeek/MCP/飞书调用不得持有数据库事务等待。
- SQLAlchemy Session生命周期由请求/任务外层管理；repository不自行commit。
- 需要并发更新的实体使用唯一约束、原子更新或显式版本号，不能只做“先查后写”。
- 幂等API使用业务幂等键和唯一约束共同保证。

## 6. 迁移标准

- 所有结构变更使用Alembic，禁止运行时 `create_all` 代替迁移。
- 一次迁移只表达一个清晰变化；revision命名语义化。
- migration必须审查upgrade/downgrade、锁表、数据回填和索引成本。
- 大表变更拆分结构、回填、切换、清理阶段；不得在一次发布中不可逆完成。
- 生产迁移使用独立迁移账号；应用账号不持有DDL权限。
- 每阶段验证空库升级、现有库升级、必要回滚和备份恢复。

## 7. ORM与DTO边界

- ORM Model只映射持久化，不直接作为FastAPI响应。
- API DTO、领域对象、工作流State和ORM Model分离并显式转换。
- repository封装查询；路由、Vue和Prompt不得依赖物理列名。
- 前端字段由OpenAPI定义，不以“数据库字段确认”作为直接集成契约。
