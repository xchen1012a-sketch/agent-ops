# ADR-0008：法律知识来源与检索策略

- 状态：已确认（**检索方式与向量库章节被 ADR-0012 修订**；其余章节继续生效）
- 日期：2026-07-04
- 阶段：DESIGN-002
- 修订：ADR-0012（混合检索：BGE-M3 dense+sparse + Qdrant + bge-reranker-v2-m3）

## 背景

法律咨询 Agent 必须基于可靠来源回答，不得伪造法条、案号或结论。课件原带知识库的具体形态在本次对齐中未提供样本，需要预留接入点；同时需要决定检索方式、引用格式与高风险问题的处理路径。

## 决策

- 知识来源：课件原有法律知识库作为初始数据；管理员可后续替换或补充。
- 检索方式：RAG（检索增强生成），Embedding 后入向量库，按问题相似度召回 top-k 片段。
- 向量库：**[修订 by ADR-0012]** 从 Chroma 改为 Qdrant 1.12+（原生支持 dense + sparse + payload 过滤），实施混合检索。
- Embedding 模型：BGE-M3（中文效果好，CPU 可推理，无外部 API 依赖）；通过 HuggingFace TEI 服务化，输出 dense + sparse 双向量。
- 联网检索：不允许联网检索外部法律数据，避免合规风险与来源不可控。
- 引用格式：回答必须附 **来源名称 + 章节 + 原文片段（<200 字）**；检索不到可靠来源时显式说明"未在知识库中找到对应依据"，不得编造。
- 高风险问题升级：检测到刑事、自杀、人身安全、紧急求助等关键词时，输出风险提示并提供线下专业渠道，转人工审核队列（不直接拒绝）。
- 免责声明：每条回答强制附加"仅供参考，不构成法律意见"。
- 知识更新：管理员手动上传新版本 + 版本号 + 操作审计；不实现自动定时抓取。

## 后果

- 法律 Agent 必须依赖 Embedding 服务运行；冷启动时需完成知识库索引构建。
- 课件知识库的具体形态（FAQ、结构化 JSON、纯文本、PDF）需要用户在 LEGAL-120 启动前提供样本，以便确定解析与切片策略。
- 无知识库命中时回答能力降级为"无法回答 + 建议"，不再生成具体法律结论。
- 高风险升级路径需要管理员审核队列，影响首响应延迟。

## 关键实现约束

- 知识库路径、Embedding 模型名、top-k、相似度阈值、高风险关键词清单均通过类型化 Settings 注入。
- 知识库版本、来源元数据存入 `legal_agent_db`；正文不入库，按文件路径引用。
- Prompt 模板独立版本管理，不在代码中硬编码。

## 待用户提供

- 课件知识库样本（任意形态，用于 LEGAL-120 切片与索引设计）。
- 是否需要预置的初始法律知识材料。

## 回滚

若 RAG 效果不达标或课件知识库无法数字化，可降级为结构化 FAQ 模板匹配；如完全无知识库，则法律 Agent 仅提供一般性法律信息与免责声明，不回答具体案例。
