# ADR-0004：禁止硬编码并遵守框架规范

- 状态：已确认
- 日期：2026-07-04

## 背景

用户再次明确要求：后续开发禁止硬编码，必须遵守当前项目开发规则和所采用开源框架的官方规范，确保多仓项目以一致、可维护、可验证的方式开发。

## 决策

- 五个仓库及父协调目录均把 `.ai-spec/.ai-rules/development-standards.md` 加入强制启动读取列表。
- 配置、Prompt、业务规则、指标口径、权限、SQL 白名单和跨仓 API 契约必须使用各自真源，不散落在实现代码中。
- FastAPI、LangGraph、Pydantic v2、SQLAlchemy 2、Alembic、Vue 3、Element Plus 和 DeepSeek/LangChain 集成均遵守官方推荐 API、结构和生命周期。
- 依赖引入或升级前检查官方文档、维护状态、许可证、兼容性和安全公告。
- 阶段验收必须执行对应 lint、类型、测试、契约、安全和构建门禁；未验证项不得标记通过。

## 后果

- 每个仓库需要类型化配置、明确模块边界和可自动执行的质量命令。
- 业务规则变化通过配置、迁移或版本化文档完成，避免散点修改。
- 任何为了赶进度绕开框架、硬编码临时值或修改依赖源码的实现均不能验收。

## 回滚

本决策属于用户确认的项目级硬约束，不提供静默回滚。若确有例外，必须记录新的 ADR，说明范围、期限、风险、替代措施，并取得用户明确确认。
