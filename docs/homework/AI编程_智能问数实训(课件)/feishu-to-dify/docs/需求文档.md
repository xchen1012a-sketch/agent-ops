# 飞书机器人 × Dify 工作流对接 — 需求文档

| 项目 | 说明 |
|------|------|
| 项目名称 | feishu-to-dify |
| 技术栈 | Python 3.11+、FastAPI |
| 文档版本 | v1.0 |
| 更新日期 | 2026-06-27 |
| 参考项目 | wechat-to-dify |

---

## 1. 项目背景与目标

### 1.1 背景

企业内需要通过飞书应用机器人承接用户咨询，并将对话能力交给 Dify 上已发布的工作流应用处理。本系统作为中间层，负责消息协议转换、流式内容转发与会话标识管理。

### 1.2 目标

构建一个基于 **FastAPI** 的中间服务，实现：

1. **接收** 飞书 `im.message.receive_v1` 事件（默认 **长连接** 模式）。
2. **转发** 用户消息至 Dify 工作流 API（`response_mode=streaming`）。
3. **回推** Dify 输出至飞书 **CardKit 流式卡片**，实现打字机式展示。

### 1.3 不在本期范围

- 飞书「自定义 webhook 机器人」（仅单向推送，无法接收用户消息）。
- Webhook 事件模式（预留接口，后续迭代）。
- 图片、文件、语音等非文本消息。
- Dify 工作流编排本身。

## 2. 总体架构

```
┌─────────────┐     长连接 WebSocket    ┌──────────────────┐     HTTP/SSE      ┌─────────────┐
│    飞书      │ ◄────────────────────► │  feishu-to-dify  │ ◄──────────────► │    Dify     │
│  应用机器人  │   接收消息/CardKit回复   │  (FastAPI 服务)   │  工作流 Run API   │  工作流应用  │
└─────────────┘                        └──────────────────┘                   └─────────────┘
```

### 核心数据流

1. 用户单聊或群聊 @ 机器人发送文本。
2. 飞书通过长连接推送 `im.message.receive_v1`。
3. 中间服务 3 秒内返回（handler 仅投递 async 任务）。
4. 创建 CardKit 卡片实体并发送到会话（占位「正在思考...」）。
5. 调用 Dify SSE，节流更新卡片 markdown 内容（累积全文）。
6. 工作流结束后关闭 `streaming_mode`。

## 3. 飞书对接

### 3.1 对接模式

| 模式 | 说明 | 本期 |
|------|------|------|
| **长连接（默认）** | `lark-oapi` WebSocket，无需公网 URL | **已实现** |
| **Webhook** | POST 至公网 HTTPS，AES 解密 | 预留 |

### 3.2 权限

- `im:message`、`im:message:send_as_bot`
- `im:message.p2p_msg:readonly` 或 `im:message.group_at_msg:readonly`
- `cardkit:card:write`

### 3.3 流式回复（CardKit）

| 步骤 | API |
|------|-----|
| 创建卡片 | `POST /open-apis/cardkit/v1/cards` |
| 发送卡片 | `POST /open-apis/im/v1/messages` |
| 更新内容 | `PUT .../cards/{id}/elements/{eid}/content` |
| 结束流式 | `PATCH .../cards/{id}/settings` |

约束：每次更新传 **累积全文** + 严格递增 `sequence`；卡片建议控制在 30KB 以内。

### 3.4 配置项

| 配置键 | 说明 |
|--------|------|
| `FEISHU_APP_ID` | 自建应用 App ID |
| `FEISHU_APP_SECRET` | 自建应用 App Secret |
| `FEISHU_MODE` | `websocket`（默认） |

---

## 4. Dify 对接

与 wechat-to-dify 一致：

- `POST {DIFY_API_BASE}/workflows/run`
- Header: `Authorization: Bearer {DIFY_API_KEY}`
- Body: `inputs`, `response_mode=streaming`, `user`
- 用户标识：`feishu_{open_id}_{chat_id}`

---

## 5. 非功能需求

- 消息去重：`message_id`，TTL 默认 600s。
- CardKit 更新节流：默认 1.0s。
- 错误映射：超时、Dify 失败、人工介入等友好中文提示。
- 日志：loguru，独立 feishu 用户访问日志。
