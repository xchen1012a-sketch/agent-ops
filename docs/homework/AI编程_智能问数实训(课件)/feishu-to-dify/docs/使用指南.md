## 1. 前置条件

| 项目 | 要求 |
|------|------|
| Python | 3.11 或更高 |
| 网络 | 服务器能访问公网（飞书长连接需要） |
| 飞书 | 有企业管理员权限或可创建/安装自建应用 |
| Dify | 已部署 Dify（云服务或自托管均可） |

**不需要**：公网域名、内网穿透（长连接模式下）。

---

## 2. 架构与流程

```
用户（飞书） → 飞书开放平台（长连接推送事件）
            → feishu-to-dify（本服务）
            → Dify 工作流 API（SSE）
            → CardKit 流式卡片回显到飞书
```

**单次对话流程：**

1. 用户在单聊或群聊 @ 机器人发送文本。
2. 飞书推送 `im.message.receive_v1` 事件到本服务。
3. 本服务创建 CardKit 卡片，显示「正在思考...」。
4. 调用 Dify `POST /v1/workflows/run`（streaming）。
5. 按节流间隔更新卡片内容为累积全文。
6. 工作流结束后关闭卡片流式模式，展示完整回复。

## 3. 第一步：创建飞书应用

### 3.1 创建企业自建应用

1. 打开 [飞书开发者后台](https://open.feishu.cn/app)。
2. 点击 **创建企业自建应用**，填写名称与描述。
3. 进入应用 → **添加应用能力** → 启用 **机器人**。

### 3.2 申请权限

在 **权限管理** 中搜索并开通（至少）：

| 权限 | 用途 |
|------|------|
| `im:message` | 获取与发送消息 |
| `im:message:send_as_bot` | 以机器人身份发消息 |
| `im:message.p2p_msg:readonly` | 接收单聊消息 |
| `im:message.group_at_msg:readonly` | 接收群聊 @ 机器人消息（若需在群里使用） |
| `cardkit:card:write` | 创建与流式更新 CardKit 卡片 |

> 若只在单聊使用，可只开 `p2p_msg`；若只在群聊使用，需开 `group_at_msg`。

### 3.3 发布并安装

1. **版本管理与发布** → 创建版本 → 申请发布。
2. 企业管理员 **安装** 应用到本企业。
3. **权限变更后必须重新发布并更新安装**，否则新权限不生效。

### 3.4 获取凭证

进入 **凭证与基础信息**，记录：

- **App ID**（形如 `cli_xxxxxxxx`）→ `FEISHU_APP_ID`
- **App Secret** → `FEISHU_APP_SECRET`

> **安全提示**：App Secret 仅保存在本地 `.env`，不要写入代码或提交到 Git。

### 3.5 配置事件订阅（长连接）

**顺序很重要：必须先启动本服务，再在后台保存配置。**

1. 完成 [第五步](#5-第三步部署本服务) 中的服务启动，确认日志出现：
   ```text
   connected to wss://msg-frontier.feishu.cn/ws/v2?...
   ```
2. 进入 **事件与回调 → 事件配置**。
3. **订阅方式** 选择：**使用长连接接收事件**。
4. **添加事件**：`im.message.receive_v1`（接收消息 v1.0）。
5. 点击 **保存**。

若保存失败，常见原因：本地服务未运行、App ID/Secret 错误、网络无法连飞书。

### 3.6 在飞书中找到机器人

- **单聊**：在飞书搜索应用/机器人名称，进入对话。
- **群聊**：群设置 → 群机器人 → 添加本应用机器人。

## 4. 第二步：配置 Dify 工作流

### 4.1 创建工作流应用

1. 登录 Dify（例如自托管 `http://localhost` 或 [Dify Cloud](https://cloud.dify.ai)）。
2. 创建 **工作流（Workflow）** 类型应用。
3. 在开始节点添加 **文本输入变量**，例如变量名 `query`（与 `DIFY_INPUT_KEY` 一致）。
4. 编排 LLM、知识库等节点，确保有文本输出。
5. 点击 **发布**（未发布的工作流无法通过 API 调用）。

### 4.2 获取 API Key

1. 进入已发布应用的 **访问 API** / **Develop** 页面。
2. 创建 API Key（形如 `app-xxxxxxxx`）→ `DIFY_API_KEY`。

### 4.3 确认 API 地址

| 部署方式 | `DIFY_API_BASE` 示例 |
|----------|----------------------|
| 自托管（本机） | `http://localhost/v1` |
| 自托管（Docker 同机） | `http://127.0.0.1/v1` 或实际域名 |
| Dify Cloud | `https://api.dify.ai/v1` |

可用 curl 快速验证（将密钥替换为你的）：

```bash
curl -X POST "http://localhost/v1/workflows/run" \
  -H "Authorization: Bearer app-xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d "{\"inputs\":{\"query\":\"你好\"},\"response_mode\":\"blocking\",\"user\":\"test\"}"
```

返回 JSON 且无 401/404 即表示 Key 与地址正确。

## 5. 第三步：部署本服务

### 5.1 克隆与安装

```bash
git clone <your-repo-url>
cd feishu-to-dify

python -m venv .venv
```

**Windows（PowerShell / CMD）：**

```bash
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

**macOS / Linux：**

```bash
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

### 5.2 编辑 `.env`

```env
APP_HOST=0.0.0.0
APP_PORT=8000
LOG_LEVEL=INFO

FEISHU_MODE=websocket
FEISHU_APP_ID=cli_xxxxxxxx
FEISHU_APP_SECRET=your-app-secret

DIFY_API_BASE=http://localhost/v1
DIFY_API_KEY=app-xxxxxxxx
DIFY_INPUT_KEY=query
DIFY_TIMEOUT=120

MSG_DEDUP_TTL=600
WS_STREAM_PUSH_INTERVAL=1.0
```

### 5.3 启动

在项目根目录执行（推荐）：

```bash
python -m app.main
```

**启动成功标志：**

```text
feishu websocket runner thread started
started in Feishu WebSocket (long connection) mode
feishu websocket connecting app_id=cli_xxxxxxxx
connected to wss://msg-frontier.feishu.cn/ws/v2?...
```

### 5.4 健康检查

浏览器或 curl：

```bash
curl http://localhost:8000/health
```

期望响应：

```json
{"status":"ok","feishu_mode":"websocket"}
```

## 6. 配置说明

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `APP_HOST` | `0.0.0.0` | HTTP 监听地址 |
| `APP_PORT` | `8000` | HTTP 端口 |
| `LOG_LEVEL` | `INFO` | 日志级别：`DEBUG` / `INFO` / `WARNING` |
| `FEISHU_MODE` | `websocket` | 当前仅实现 `websocket` |
| `FEISHU_APP_ID` | — | 飞书 App ID |
| `FEISHU_APP_SECRET` | — | 飞书 App Secret |
| `FEISHU_API_BASE` | `https://open.feishu.cn` | 飞书 API 域名，一般无需改 |
| `DIFY_API_BASE` | `http://localhost/v1` | Dify API 根路径 |
| `DIFY_API_KEY` | — | Dify 工作流 API Key |
| `DIFY_INPUT_KEY` | `query` | 工作流开始节点输入变量名 |
| `DIFY_TIMEOUT` | `120` | 调用 Dify 超时（秒） |
| `MSG_DEDUP_TTL` | `600` | 同一 `message_id` 去重 TTL（秒） |
| `WS_STREAM_PUSH_INTERVAL` | `1.0` | CardKit 更新最小间隔（秒），建议 ≥1 |
| `WELCOME_MESSAGE` | 中文默认欢迎语 | 预留，当前版本未主动发送 |

## 7. 第四步：联调与验证

### 7.1 单聊测试

1. 在飞书打开与机器人的单聊。
2. 发送：`你好`。
3. 预期：
   - 出现卡片，先显示「正在思考...」；
   - 内容逐步更新为 Dify 输出；
   - 最终定格为完整回答。

### 7.2 群聊测试

1. 将机器人加入群聊。
2. 发送：`@机器人名称 你好`（必须 @ 机器人）。
3. 预期与单聊相同。

### 7.3 日志观察

成功处理消息时，控制台可能出现类似日志：

```text
[Feishu用户] open_id=ou_xxx | chat_id=oc_xxx | message_id=om_xxx | query=你好
dify finished message_id=om_xxx task_id=... len=...
```

### 7.4 运行单元测试

```bash
pytest
```

## 8. 常见问题

### 长连接保存失败

| 原因 | 处理 |
|------|------|
| 服务未启动 | 先 `python -m app.main`，看到 `connected to wss://...` 再保存 |
| Secret 错误 | 核对 `.env` 与开发者后台 |
| 非自建应用 | 长连接仅支持企业自建应用 |

### 发消息无反应

| 原因 | 处理 |
|------|------|
| 未订阅事件 | 确认已添加 `im.message.receive_v1` |
| 群聊未 @ | 群聊必须 @ 机器人 |
| 权限未生效 | 重新发布应用并更新安装 |
| 机器人未进群 | 群设置中添加机器人 |

### 有事件但无卡片 / 报错

| 原因 | 处理 |
|------|------|
| 缺少 `cardkit:card:write` | 权限管理中添加并重新发布 |
| Token 失败 | 检查 App ID/Secret，看日志中 `FeishuApiError` |

### Dify 相关错误

| 现象 | 处理 |
|------|------|
| HTTP 401 | API Key 错误或过期，在 Dify 重新创建 |
| HTTP 404 | `DIFY_API_BASE` 错误或工作流未发布 |
| 卡片显示「处理失败」 | 看服务日志中 Dify 返回；检查 `DIFY_INPUT_KEY` 是否与开始节点变量名一致 |
| 超时 | 增大 `DIFY_TIMEOUT` 或简化工作流 |

### 重复回复

同一 `message_id` 在 `MSG_DEDUP_TTL` 内会去重。若飞书重推事件，属正常现象。

## 9. 生产环境建议

1. **进程守护**：使用 systemd、supervisor 或 Docker 保持 `python -m app.main` 常驻。
2. **单实例长连接**：同一飞书应用全局仅一个有效长连接；多实例部署需改用 Webhook 模式（本项目尚未实现）。
3. **密钥管理**：生产环境用环境变量或密钥管理服务注入，不要硬编码。
4. **日志**：可将 `LOG_LEVEL=INFO`，必要时对 `app.feishu.user` 日志做访问审计。
5. **Dify 与网络**：确保本服务能稳定访问 `DIFY_API_BASE`；自托管 Dify 注意 Docker 网络与端口。

**systemd 示例（Linux）：**

```ini
[Unit]
Description=feishu-to-dify
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/feishu-to-dify
EnvironmentFile=/opt/feishu-to-dify/.env
ExecStart=/opt/feishu-to-dify/.venv/bin/python -m app.main
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

## 10. 发布到 GitHub 前的检查清单

在 `git push` 前请确认：

- [ ] `.env` **未** 被跟踪（已在 `.gitignore` 中）
- [ ] 仅提交 `.env.example`（占位符，无真实密钥）
- [ ] `.idea/`、`.venv/` 未提交（已在 `.gitignore` 中）
- [ ] 代码与文档中无 App Secret、Dify API Key、服务器密码
- [ ] 启动日志截图已打码 App ID / 连接 ticket（若公开分享）
- [ ] 若密钥曾误提交或泄露：**立即** 在飞书重置 App Secret、在 Dify 轮换 API Key

**初始化 Git 并首次提交（示例）：**

```bash
cd feishu-to-dify
git init
git add .
git status   # 确认 .env、.venv、.idea 不在列表中
git commit -m "Initial commit: Feishu bot bridge for Dify workflow"
git remote add origin https://github.com/<user>/feishu-to-dify.git
git push -u origin main
```
