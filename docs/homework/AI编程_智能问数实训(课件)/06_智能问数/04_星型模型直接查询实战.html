## SQL 生成规则
1. 仅生成 SELECT 语句，禁止 INSERT/UPDATE/DELETE/DROP
2. 金额使用 ROUND(..., 2) 保留两位小数
3. 排除已取消（status_key=5）和已退款（status_key=6）的订单
4. 排名使用 ORDER BY ... DESC LIMIT N
5. 只输出纯 SQL，不要任何额外解释

逐题结果分析

✅ Q1（2 表 JOIN）：2026 年 5 月的总销售额

xxxxxxxxxx
-- LLM 生成 ✅ 正确
SELECT ROUND(SUM(o.actual_amount), 2) AS 总销售额
FROM fact_orders o
JOIN dim_date d ON o.order_date_key = d.date_key
WHERE d.year = 2026 AND d.month = 5
  AND o.order_status_key NOT IN (5, 6);

✅ Q2（3 表 JOIN）：各渠道的订单量和销售额排行

xxxxxxxxxx
-- LLM 生成 ✅ 正确
SELECT ch.channel_name AS 渠道,
       COUNT(DISTINCT o.order_key) AS 订单量,
       ROUND(SUM(o.actual_amount), 2) AS 销售额
FROM fact_orders o
JOIN dim_channel ch ON o.channel_key = ch.channel_key
JOIN dim_date d ON o.order_date_key = d.date_key
WHERE d.year = 2026 AND d.month = 5
GROUP BY ch.channel_name
ORDER BY 销售额 DESC;

✅ Q5（3 表 JOIN）：金卡会员的人均消费

xxxxxxxxxx
-- LLM 生成 ✅ 正确
SELECT ROUND(SUM(o.actual_amount) / COUNT(DISTINCT c.customer_key), 2) AS 人均消费
FROM fact_orders o
JOIN dim_customer c ON o.customer_key = c.customer_key
WHERE c.customer_level = '金卡';

⚠️ Q8（5 表 JOIN）：手机品类下各品牌的销售额排名

xxxxxxxxxx
-- LLM 生成（⚠️ 有一处关联字段错误）
SELECT p.brand,
       ROUND(SUM(od.sub_total), 2) AS 销售额
FROM fact_order_details od
JOIN dim_product p ON od.product_key = p.product_key       -- ✅ 正确
JOIN dim_product_category pc ON p.product_key = pc.category_key  -- ❌ 错误！
WHERE pc.category_name = '手机通讯'                         -- ✅ 筛选条件正确
GROUP BY p.brand
ORDER BY 销售额 DESC;

错误分析：p.product_key = pc.category_key 应该是 p.category_key = pc.category_key。 product_key 是商品维度的主键，category_key 才是品类维度的外键。LLM 混淆了这两个字段。

❌ Q9（7 表 JOIN）：华东区金卡会员通过 App 购买手机品牌 TOP5

xxxxxxxxxx
-- LLM 生成（多处潜在问题）
SELECT p.brand, ROUND(SUM(od.sub_total), 2) AS 销售额
FROM fact_order_details od
JOIN fact_orders o         ON od.order_key = o.order_key         -- ✅
JOIN dim_product p         ON od.product_key = p.product_key      -- ✅
JOIN dim_product_category pc ON p.category_key = pc.category_key  -- ✅
JOIN dim_customer c        ON o.customer_key = c.customer_key     -- ✅
JOIN dim_region r          ON o.region_key = r.region_key         -- ✅
JOIN dim_channel ch        ON o.channel_key = ch.channel_key      -- ✅
WHERE pc.category_name = '手机通讯'
  AND r.region_name = '华东'          -- ⚠️ 实际值是 '华东' 还是 '华东区'？
  AND c.customer_level = '金卡'       -- ✅
  AND ch.channel_name = 'App 商城'    -- ⚠️ 实际值是 'App 商城' 还是 'APP商城'？
GROUP BY p.brand
ORDER BY 销售额 DESC
LIMIT 5;

7 表 JOIN！ 核心问题：

  • LLM 不知道枚举值的精确写法（'华东' vs '华东区'，'App 商城' vs 'APP商城'）
  • 注意力被 7 张表的关联关系严重分散

💸 注意力稀释效应：为什么 JOIN 越多问题越大

xxxxxxxxxx
单表 (Q1):     ████████████████████ 100% 注意力 → 准确率 95%+
2-3表 (Q2-7):  ████████████░░░░░░░░  65% 注意力 → 准确率 85%
4-5表 (Q8):    ████████░░░░░░░░░░░░  40% 注意力 → 准确率 70%
6-7表 (Q9-10): ████░░░░░░░░░░░░░░░░  20% 注意力 → 准确率 45%

每多 JOIN 一张表，LLM 需要在 Prompt 中多理解一个完整表结构，并在生成 SQL 时多匹配一个精确关联条件。当 JOIN 达到 7 张表时，LLM 的有效注意力已被稀释到难以准确选择正确字段的程度。

🛠️ 缓解策略（临时方案，治标不治本）

策略 1：创建视图封装常用 JOIN

xxxxxxxxxx
-- 将常用维度预 JOIN 成视图
CREATE VIEW v_order_summary AS
SELECT
    o.order_key, o.actual_amount, o.item_count,
    d.date_value AS order_date,
    d.year AS order_year, d.month AS order_month,
    c.customer_level, c.age_group,
    ch.channel_name,
    r.region_name,
    os.status_name
FROM fact_orders o
JOIN dim_date d           ON o.order_date_key = d.date_key
JOIN dim_customer c       ON o.customer_key = c.customer_key
JOIN dim_channel ch       ON o.channel_key = ch.channel_key
JOIN dim_region r         ON o.region_key = r.region_key
JOIN dim_order_status os  ON o.order_status_key = os.order_status_key;
  • ✅ 减少了部分 JOIN
  • ❌ 视图只覆盖了订单维度，不包含商品/品类维度
  • ❌ 多个视图之间仍需 JOIN
