# 📤 参数提取节点 — 简历信息提取

> **核心作用**：参数提取节点利用 LLM 从非结构化文本中提取结构化数据。你定义「要提取什么字段」，它自动从用户输入的文本中抽取并填充。非常适合表单自动填写、文档信息提取等场景。

---

## 🎯 学习目标

学完本案例后，你将能够：
- 配置参数提取节点，定义提取字段及类型
- 理解参数提取与 LLM + 代码提取的区别
- 将提取结果传给下游节点进行业务处理
- 处理提取失败或信息缺失的情况

---

## 📚 案例描述

构建一个「**简历信息自动提取器**」，用户粘贴一段简历文本，系统自动提取姓名、电话、邮箱、学历、工作年限等结构化信息，然后由 LLM 生成岗位匹配度评估。


## 🔧 手把手实操

### 步骤 1：创建工作流

1. 创建应用 → 「工作流」
2. 命名为：`简历信息提取器`

### 步骤 2：配置开始节点

| 字段名 | 类型 | 必填 | 说明 |
|:---|:---|:---:|------|
| `resume_text` | 段落文本 | ✅ | 简历文本内容 |
| `position` | 文本 | ✅ | 应聘岗位（如「大数据工程师」） |

### 步骤 3：配置参数提取节点（核心）

1. 拖入「**参数提取**」节点
2. 连接：`开始` → `参数提取`
3. 模型选择：`deepseek-v4-flash`（提取任务用快模型即可）

#### 定义提取字段

在右侧配置面板中点击「添加参数」，定义以下字段：

| 参数名 | 类型 | 必填 | 描述（给 LLM 看的提取提示） |
|------|------|:---:|------|
| `name` | 文本 | ✅ | 从简历中提取的姓名 |
| `phone` | 文本 | ❌ | 手机号码，11 位数字 |
| `email` | 文本 | ❌ | 电子邮箱地址 |
| `education` | 下拉选项 | ✅ | 最高学历：高中/大专/本科/硕士/博士 |
| `years_of_work` | 数字 | ❌ | 工作年限（年） |
| `skills` | 数组[文本] | ✅ | 技能列表（编程语言、框架、工具等） |
| `last_company` | 文本 | ❌ | 最近一家公司的名称 |
| `expected_salary` | 文本 | ❌ | 期望薪资（如有提及） |

#### 提取指令（Instruction）

在「指令」输入框中，给 LLM 提供提取指导：

```
请从以下简历文本中提取关键信息。
- 如果某项信息在简历中未提及，留空即可
- 学历请从选项中选择最匹配的一项
- 技能请拆分为列表，如 "Python, SQL, Hadoop"
- 工作年限请提取数字部分，如"3年" → 3
```

> 💡 **参数描述的重要性**：描述越清晰，LLM 提取越准确。描述是给 LLM 看的「字段定义说明」。

### 步骤 4：用代码节点验证提取结果

1. 拖入「代码执行」节点（Python）
2. 连接：`参数提取` → `代码执行`
3. 输入变量：提取出的所有字段

```python
def main(name: str, phone: str, email: str, education: str,
         years_of_work, skills: list, last_company: str, expected_salary: str) -> dict:
    """验证提取结果的完整性"""
    
    issues = []
    
    # 必填字段检查
    if not name or len(name.strip()) < 2:
        issues.append("⚠️ 姓名未提取到或异常")
    if not education:
        issues.append("⚠️ 学历未识别")
    if not skills or len(skills) == 0:
        issues.append("⚠️ 技能列表为空")
    
    # 数据质量检查
    if phone and len(phone.replace('-', '').replace(' ', '')) < 11:
        issues.append("⚠️ 电话号码格式可能异常")
    if email and '@' not in email:
        issues.append("⚠️ 邮箱格式可能异常")
    
    # 处理 years_of_work 可能为 None
    work_years = years_of_work if years_of_work else 0
    
    return {
        "is_valid": len(issues) == 0,
        "issues": issues,
        "profile": {
            "name": name,
            "phone": phone or "未提供",
            "email": email or "未提供",
            "education": education,
            "work_years": work_years,
            "skills": skills or [],
            "last_company": last_company or "未提供",
            "expected_salary": expected_salary or "未提及"
        }
    }
```

### 步骤 5：配置 LLM 节点生成匹配评估

1. 拖入 LLM 节点，连接：`代码执行` → `LLM`
2. 模型：`deepseek-v4-pro`（评估任务用强模型）

**User Prompt**：
```
应聘岗位：{{#start.position#}}

候选人信息：
- 姓名：{{#code.profile.name#}}
- 学历：{{#code.profile.education#}}
- 工作年限：{{#code.profile.work_years#}} 年
- 技能：{{#code.profile.skills#}}
- 最近公司：{{#code.profile.last_company#}}

请评估该候选人与岗位的匹配度：
1. 技能匹配度（高/中/低）
2. 经验匹配度（高/中/低）
3. 综合评分（1-10 分）
4. 面试建议（50 字以内）

如果信息不完整（{{#code.is_valid#}}），请指出缺失的关键信息。
```

### 步骤 6：结束节点

输出变量：`{{#llm.text#}}`

### 步骤 7：测试

输入简历文本：
```
张三 | 13812345678 | zhangsan@email.com

教育背景：
北京大学 计算机科学 硕士 2020年毕业

工作经历：
2022-至今 字节跳动 大数据开发工程师
2020-2022 阿里巴巴 Java开发工程师

技能：Python, SQL, Hadoop, Spark, Flink, Hive

期望薪资：30K-40K
```

选择应聘岗位：`大数据工程师`

> **期望输出**：
> - 参数提取：自动填充姓名、电话、邮箱、学历=硕士、工作年限≈6年、技能列表
> - LLM 评估：高技能匹配、高经验匹配、综合评分 8-9 分

## 📤 参数提取 vs 其他方案

| 方案 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **参数提取节点** | 内置 LLM 提取 + Dify UI 解析 | 开箱即用、可视化配置参数 | 灵活性一般 |
| **LLM + 代码手动解析** | LLM 输出 JSON → 代码解析 | 完全自定义 | 需编写解析逻辑 |
| **正则表达式** | 模式匹配 | 极快、不消耗 Token | 无法理解语义 |

> 💡 **建议**：结构化信息提取 → 参数提取节点；复杂自定义提取 → LLM + 代码节点。

---

## 💡 避坑指南

| 常见问题 | 原因 | 解决方案 |
|------|------|------|
| 某个字段总是提取不到 | 参数描述不够清晰 | 优化「描述」栏，举例说明 |
| 提取的值格式不符合预期 | 未约束输出格式 | 在描述中明确格式要求 |
| 技能列表被提取为单条文本 | 未标记为数组类型 | 参数类型选「数组[文本]」 |
| 数字类型提取失败 | 文本中数字格式多样 | 描述中要求「只提取数字部分」 |
