# DESIGN-002 模块详细设计对齐

## 目标

在任何编码前，逐模块确认业务流程、数据模型、API Schema、安全边界、验收数据和前端交互，并把确认结果写回各仓真源规格。

## 范围

1. 法律咨询：知识来源、账户边界、会话/消息模型、导出与隐私策略。
2. 智能招聘：文件格式、匹配口径、公平性规则、材料保留和验收样本。
3. 智能问数：指标字典、SQL 白名单、查询 adapter、评测集和飞书边界。
4. 统一前端：身份认证、菜单/路由、SSE 状态、视觉系统和错误交互。
5. 运维：开发数据库拓扑、端口、环境变量命名和镜像版本约定。
6. Agent运行时：默认LangGraph；按模块记录是否需要Deep Agents评估及选择门槛。

## 不做事项

- 不创建应用代码、依赖、迁移或容器配置。
- 不连接 DeepSeek、MySQL 或飞书。
- 不把待确认设计写成已确认事实。

## 验收标准

- 每个模块的待确认问题有用户结论。
- 数据实体、主要字段、唯一性、生命周期和权限边界明确。
- API 请求、响应、错误和 SSE 事件 Schema 明确。
- 每个 LangGraph 节点的输入、输出、失败、重试和幂等语义明确。
- 验收样本、成功指标和停止条件明确。
- 用户明确同意进入 `FOUND-010` 后才允许编码。
- 每个Agent明确“自定义LangGraph”或“需要Deep Agents对比Spike”，未评估不得直接引入依赖。

## 回滚方式

详细设计只修改文档。若方案被否决，保留 ADR 记录并将规格恢复到最后一次用户确认的版本，不修改代码。
