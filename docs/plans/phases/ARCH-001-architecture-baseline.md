# ARCH-001 多仓架构与文档基线

## 目标

在不编写业务代码的前提下，建立后续开发必须遵循的计划、仓库边界、架构决策、模块规格和 API 草案。

## 范围

- 建立父目录非 Git 计划体系。
- 在 `agents/` 下集中放置三个 Agent 子仓，并与前端、运维仓共同组成 5 个独立 Git 子仓；默认分支为 `main`。
- 为每个子仓建立项目级规则入口、README 和架构/规格文档。
- 在运维协调仓库记录跨仓架构、ADR、API 约定、可观测性和部署拓扑。
- 建立三个 Agent 的模块子阶段计划。

## 不做事项

- 不安装 Python、Node 或 Docker 依赖。
- 不创建可执行应用入口、业务代码、数据库迁移或 Compose 文件。
- 不调用 DeepSeek、飞书或 MySQL。
- 不执行 `git add`、`git commit`、`git push`。

## 验收标准

- 父目录不存在 `.git`。
- 5 个约定子目录各自存在独立 `.git`，默认分支为 `main`。
- 每个仓库具有独立职责说明和禁止跨界事项。
- 总体架构文档描述请求链路、数据边界、部署边界和失败隔离。
- 三个 Agent 规格包含课件原文依据、迁移解释、功能范围和未决事项。
- API 草案包含请求、响应、错误、流式和运行状态约定。
- 文件扫描确认未创建 `.py`、`.vue`、`.ts`、`.js` 或可执行 Compose 配置。

## 验收证据

- 2026-07-04：父目录 `.git` 不存在，`agents/` 容器目录 `.git` 不存在。
- 2026-07-04：5 个子仓均初始化为独立 Git 仓库，当前分支均为 `main`，提交数均为 0。
- 2026-07-04：5 个子仓的 `.ai-spec/scripts/check.ps1` 均通过。
- 2026-07-04：必需 README、架构、规格、ADR、契约和运维设计文件全部存在。
- 2026-07-04：排除项目规则目录后，业务代码文件数量为 0。
- 2026-07-04：`package.json`、`pyproject.toml`、`requirements.txt`、Dockerfile 和可执行 Compose 文件数量为 0。

结论：`ARCH-001` 验收通过。

## 回滚方式

本阶段仅新增目录和文档。如需回滚，先列出新增路径并经用户确认后删除；不得删除课件、作业模板或现有 `.ai-spec`。

## 停止条件

- 仓库命名或职责边界发生变化。
- 需要新增第四个业务服务或共享业务运行库。
- 文档要求与课件原文冲突且无法通过迁移说明消解。
