# 运维协调模块详细计划

## 1. 模块身份

- 仓库：`agent-suite-ops`
- 真源：`docs/architecture/`、`docs/adr/`、`docs/contracts/`、`docs/runbooks/`
- 职责：统一编排、网关、环境模板、健康检查、可观测与部署文档

## 2. 目标与成功标准

支持五仓各自独立部署及统一 Docker Compose 编排。运维仓只引用版本化镜像和公开健康/API 契约，不挂载其他仓库源码、不承载业务逻辑。

成功标准：三个 Agent 可单独启动；统一环境可一键启动/停止；健康依赖、最小权限、Secret 外置、日志关联和回滚流程可验证。

## 3. 范围

- 镜像/服务命名、端口、网络、卷和环境变量规范。
- 统一 Compose、反向代理、健康检查和启动顺序。
- MySQL 8 开发拓扑、独立数据库/账号和初始化边界。
- 日志、指标、trace 关联约定和可选本地观测栈。
- 部署、备份、恢复、升级、回滚和排障 Runbook。

## 4. 不做事项

- 不承载 Agent、前端或数据库业务逻辑。
- 不保存总体计划、真实 Secret、生产数据或用户材料。
- 不使用 `latest` 等不可追踪镜像标签。
- 不通过共享源码卷制造跨仓运行耦合。

## 5. 前置决策（OPS-610）

- 服务名、端口区间、网络和域名/API 前缀。
- MySQL：`legal_agent_db`、`recruitment_agent_db`、`data_query_agent_db` 与只读 `shop_db` 权限模型。
- DeepSeek、飞书和数据库 Secret 注入方式。
- 本地统一认证依赖和网关责任边界。
- 可观测栈是否纳入首期，以及资源预算。

## 6. 子阶段

### OPS-610 部署详细设计

- 产物：部署拓扑、服务/端口表、变量字典、权限矩阵、镜像兼容矩阵和故障矩阵。
- 验证：每项配置有负责人和真源；用户确认。

### OPS-620 仓库独立容器标准

- 工作：定义非 root、多阶段构建、健康检查、固定版本、最小上下文和 Secret 外置标准。
- 验证：每仓 Docker build、镜像扫描和独立启动通过。

### OPS-630 MySQL 开发拓扑

- 工作：建立四个逻辑数据库/权限域；`shop_db` 查询账号只读，智能问数运行态写入 `data_query_agent_db`。
- 验证：越权读写测试、迁移账号与运行账号隔离、备份恢复演练通过。

### OPS-640 统一 Compose 与网关

- 工作：只引用各仓版本化镜像，配置网络、依赖、健康和反向代理。
- 验证：全量启动、单服务重启、单服务下线隔离、统一停止通过。

### OPS-650 可观测与排障

- 工作：结构化日志、request/thread/run ID 关联、RED 指标、敏感字段过滤和 Runbook。
- 验证：模拟 DeepSeek、MySQL、飞书、SSE 故障能定位到服务/节点/错误码。

### OPS-660 发布与回滚验收

- 工作：版本矩阵、升级顺序、数据库迁移门禁、回滚和灾备说明。
- 验证：无数据丢失的升级/回滚演练；文档步骤可由另一环境复现。

## 7. 配置与禁止硬编码

端口、镜像、域名、超时、账号和功能开关全部通过环境模板或部署变量注入。`.env.example` 只给占位和说明；真实 Secret 不进入 Git、日志和截图。

## 8. 风险与停止条件

- 某服务只能依赖源码挂载才能运行。
- `shop_db` 查询账号拥有写权限。
- 统一编排要求改变 Agent 内部业务逻辑。
- 依赖版本、许可证或镜像来源不可追踪。

出现任一项时停止实施并更新 ADR/计划。
